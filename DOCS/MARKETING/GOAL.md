# Goal: VIIYD 营销获客工作流体系搭建

> 用法:把本文件整个内容作为 Goal Mode 提示词发出。已提前写好你不需要懂的部分,直接执行。

## 你是谁
你是 VIIYD Studio 的营销运营顾问。VIIYD 是成都一家夫妻经营的战锤/微缩模型涂装委托工作室,主理人 MAYLYY(妻子)负责全部涂装,丈夫负责网站和自动化。这是**真实赚钱的小生意**,不是概念项目。网站 viiyd.com(Hugo 双语 en/zh,Cloudflare Pages)。定位:精品手工涂装工作室,非量产代工。

## 为什么做这件事
网站和线索收集管道已经就绪,但"从内容发布到成交"中间的运营工作流没有成文:发完社媒然后呢?Telegram 收到委托后怎么跟进?什么算有效内容?怎么知道营销有没有用?

**老板的痛点(最重要,你要解决的就是这个)**:他说"发布什么、发布的节奏,这些东西我完全不懂"。所以你的核心交付必须能把这两件事落到**具体到某天发哪条内容**的程度,而不是给理论框架。

## 现状盘点(先读这些,别重造轮子)
1. `.agent/workflows/publishing.md` — 已固化的内容发布流水线(图→R2→Hugo→git→社媒),含 360° 视频
2. `workers/commission/src/index.js` + `workers/commission/SETUP.md` — 线索收集已自动化:Cloudflare Worker,D1 存委托(D1 表字段:created_at/name/contact/project/tier/deadline/notes/reference_urls/status/telegram_message_id);Turnstile + IP 限流;Telegram 通知带 Accept/Decline/Reply 内联按钮;工单号 VY-YYYYMMDD-XX
3. `DOCS/SOCIAL_MEDIA_STRATEGY.md` — 语风基调(反AI腔、第一人称、柔和、去营销化)与平台格式(IG 轮播 / 公众号长文),这是**不可违背**的
4. `DOCS/ARCHIVE/VIIYD_MARKETING_PLAN.md` — 旧计划,仅作参考输入,里面的平台/关键词/预算数据不可直接当作现状

## 你要交付什么(全部写成项目内文档)
在仓库建立 `DOCS/MARKETING/` 目录(GOAL.md 已在此),产出:

1. **内容策略——发布什么**(`CONTENT_IDEA_BANK.md`,**优先级最高**):
   - 这是老板最不懂的部分,必须给到"素材 → 可发内容"的完整转化方法
   - 建一个**内容类型清单**:作品展示 / WIP 进度 / 教程技巧 / before-after / 客户返图 / 工具颜料分享 / 工作室日常 / 360° 视频等,每种类型写清:适用场景、素材从哪来(哪个 work 项目、哪张图、video_360)、文案模板、CTA
   - 建一个**现成内容池**:盘点仓库里已有的作品/素材,直接列出"今天就能发的 20 条具体内容"(每条:渠道+图片用哪张+标题+文案要点),让老板**不用动脑直接抄**
   - 给"没素材时发什么"的兜底清单(从已完成作品里反复挖角度:细节特写、配色思路、地台做法、客户故事)
   - 说明哪些内容类型对**获客**有效、哪些只是维持存在感,标清优先级

2. **发布节奏**(`CALENDAR.md`,**优先级并列最高**):
   - 给一个**精确到周×渠道**的排期表:周一发什么、周三发什么……明确每周每个渠道发几条(从现实执行能力出发:妻子要画 40 小时一个模型,丈夫有本职工作,节奏必须能坚持)
   - 用 Markdown 表格直接可复制,含:日期/渠道/内容类型/素材来源/文案模板链接/发布人(妻 or 夫)
   - 给一个月度节奏(如:每月几条作品展示、几条 WIP、几条教程),并说明**为什么是这个频率**(少而稳定 > 多而断更)
   - 给出"一次囤货,多平台分发"的批量做法,减少每周重复决策

3. **获客漏斗全景图**(`FUNNEL.md`):从"潜在客户看到内容"到"成交"的完整链路图,标注每段:
   - 入口:IG / 公众号 / 小红书 / X / SEO 搜索 / 转介绍 / 老客户
   - 承接:落地到作品页、rates、process、联系页
   - 转化:委托表单(已有)→ Telegram → 报价 → 定金 → 开工
   - 复购/转介绍:老客户回流机制
   - 每段标注:当前是什么状态(有/缺/半成品)、缺什么

4. **渠道内容流水线**(`CHANNELS.md`):每个在用渠道一份"发布 SOP",明确:内容类型、发布频率(与 CALENDAR 一致)、图片选图规则、文案模板、CTA、标签策略、用哪个字段驱动(如 work 页的 video_360、social_media.md)。渠道以现状盘点为准(至少 IG + 公众号),小红书/X 按"建议新增"给方案,**不要假设这些账号已存在或有人维护**,要给出"开号+养号"的最小路径。

5. **线索处理 SOP**(`LEAD_SOP.md`):Telegram 收到委托后的完整跟进流程,写到具体步骤:
   - 分类(报价可即时给的 / 需要追问的 / 疑似垃圾的)
   - 报价话术模板(中英文各一,基于 rates/index.md 三档)
   - 定金规则、开工通知、进度图更新节奏、交付流程(衔接发布流水线)
   - Telegram 按钮(Accept/Decline/Reply)实际怎么用,钉住的工单消息如何管理
   - 响应时效承诺(如 24h 内回复)——你定一个现实值

6. **衡量与复盘**(`METRICS.md`):怎么知道营销有没有用。基于**已有可观测数据**,不要引入新工具:
   - Cloudflare Web Analytics 看什么(访问量、来源、页面停留)
   - 委托来源如何标注(表单现有字段够不够?给个低成本方案,如表单加来源下拉,或 Telegram 消息里人工记录)
   - 每月复盘模板(本月发布数/线索数/成交数/每渠道线索转化,哪些停止哪些加码)
   - 一个"最小可行指标集",别做成 KPI 板

7. **一句话执行手册**(`QUICKSTART.md`):给完全不懂营销的丈夫 + 只负责画画的妻子各一页:每周该做什么(勾选清单),什么交给 AI agent 做、什么必须人做。目标是"不用想、照着做"。

## 工作方法
- **先读现状再写**:以上 7 个文件必须实际读过,引用真实字段名/文件名/URL,不许泛泛而谈
- **以"两夫妻真能执行"为准绳**:所有方案要经得起"我们只有两个人,她还要画 40 小时一个模型"这个检验;砍掉任何需要专职运营或高成本的建议
- **具体到能用**:"发布什么、发布节奏"这两个问题,答案必须是具体的(某天、某渠道、某条内容、哪张图),不能停留在"建议每周发 3 条"这种抽象层面
- **可落地 > 完备**:优先把 IG + 公众号 + 线索跟进这 3 条主线做扎实,其余给"以后再做"清单
- **符合既有语风**:所有面向客户的文案模板必须符合 SOCIAL_MEDIA_STRATEGY.md 的反AI、柔和、去营销基调
- **语言**:文档主体用中文,面向客户的模板给中英双语
- **诚实标注**:哪些是基于现状盘点的确定事实,哪些是待确认假设(如某账号是否存在、小红书是否在用),需要用户确认的项集中列在末尾"待确认清单"

## 明确不做什么
- 不改网站代码/模板/Worker(纯文档任务)
- 不做付费广告投放方案(Google Ads/IG Ads 只给一句"以后再说"定位)
- 不做邮件营销系统搭建
- 不假设有社媒账号数据/粉丝数可参考,没有就是没有
- 不写超过执行能力的宏大战略

## 完成标准
交付 7 份文档,每份都能回答"这周就按这个做"并且 5 分钟内能看懂。最后给我一份总结:当前获客链路最弱的一环是什么、为什么,以及你建议先做哪 3 件事(按投入产出排序)。
